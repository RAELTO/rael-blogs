# NBOX

Neo-brutalist social app for short-form drops, contacts, notifications, and direct messages.

**Demo:** [n-box-dev.vercel.app](https://n-box-dev.vercel.app)

## Stack

| Layer | Technology |
| --- | --- |
| Frontend | React 19, TypeScript, Vite 8 |
| Styling | Tailwind CSS 4 + custom neobrutalist design tokens |
| Routing | React Router v7 |
| Server state | TanStack Query v5 |
| Backend | Supabase Auth, Postgres, Realtime, Storage, RLS |
| Deploy | Vercel |

## Current Features

- Auth with sign up, sign in, email confirmation, password recovery, and protected routes.
- Public box permalinks plus authenticated home, explore, contacts, notifications, profile, and NBOX chat routes.
- Six drop types: quick text, media, poll, mood, link, and thread.
- Feed interactions: likes, dislikes, emoji reactions, comments, comment reactions, shares, tags, saves, and delete-own-box.
- Contacts system with incoming/outgoing requests, accept/decline flows, and contact-only messaging.
- NBOX direct messages with a full inbox view, desktop floating chat, Supabase Realtime updates, and contact status display.
- Real notifications generated from database events for reactions, votes, comments, follows, contacts, and shares.
- Realtime presence for online contacts, with `last_seen_at` as a fallback for offline status.
- Responsive neobrutalist UI with desktop sidebars, mobile top/bottom navigation, and modal portals.
- Profile editing with avatar upload, username, bio, and appearance controls.

## Safe Install

This repository pins pnpm 12 and ships supply-chain policy in `pnpm-workspace.yaml`:

```yaml
minimumReleaseAge: 10080
minimumReleaseAgeStrict: true
blockExoticSubdeps: true
strictDepBuilds: true
trustPolicy: no-downgrade
allowBuilds:
  esbuild: false
```

This delays newly published versions for seven days, rejects exotic transitive sources and blocks dependency lifecycle scripts unless they are explicitly reviewed and allowed.

Use the locked install path for normal setup:

```bash
git clone <repo-url>
cd nbox
npm install --global pnpm@12.3.4
pnpm --version
pnpm install --frozen-lockfile
cp .env.example .env
pnpm run dev
```

The one-time npm command only bootstraps the exact pnpm version pinned by the repository. Current Corepack releases can also honor the `packageManager` field, but an outdated Corepack may not recognize pnpm 12's native executable layout.

Use `pnpm add <package>` only when intentionally adding or updating dependencies. Review the `package.json` and `pnpm-lock.yaml` diff before committing. If a package truly requires an install script, review it first and add only that package to `allowBuilds`.

Find these values in Supabase under **Project Settings -> API**.

## Supabase

The schema is versioned in `supabase/migrations/`.

```bash
supabase db push
```

The migrations include:

- Core NBOX tables: profiles, boxes, tags, reactions, votes, comments, shares, follows, saves.
- Contacts and contact requests.
- Direct messaging conversations and messages.
- Unified notifications generated by Postgres triggers.
- Presence support with `last_seen_at`.
- RLS policies, indexes, security hardening, storage policies, and search functions.

Storage uses the public `post-images` bucket:

- Box media: `{user_id}/posts/{timestamp}.{ext}`
- Avatars: `{user_id}/avatar/avatar.{ext}`

## Local Browser Testing

Install the browser binaries once, copy the environment template, and provide only local test credentials:

```bash
pnpm exec playwright install chromium firefox webkit
cp e2e.env.example .env.e2e.local
pnpm run test:e2e
```

`.env.e2e.local`, authenticated browser state, reports, traces, and screenshots are ignored by Git. Visual captures wait for settled feed content and mask account identity blocks before writing PNG files under `.tmp/playwright/`.

The authenticated matrix covers 1440×900 desktop, 1024×768 landscape tablet, 768×1024 portrait tablet, 390×844 mobile, and 360×800 small mobile. It checks protected routes, responsive navigation, touch/keyboard reaction menus, horizontal overflow, and serious/critical Axe violations.

## Security Notes

- Supabase RLS protects database access; users can only mutate content they own or relationships they participate in.
- Chat reads/writes are restricted to conversation participants and conversations are only created for accepted contacts.
- Notifications are generated by Postgres triggers instead of frontend inserts, so direct API calls still produce consistent notification state.
- `sanitizeUrl()` rejects non-HTTP protocols to block `javascript:` and similar payloads.
- Upload helpers validate image type and size before writing to Storage.
- The Supabase anon key is public by design; RLS is the real authorization boundary.
- Dependency install scripts are denied by default through `allowBuilds` in `pnpm-workspace.yaml`.
